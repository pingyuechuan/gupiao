# 10 — 数据指标与埋点规范（Analytics）

版本：`0.7 设计 / 0.8 实施`　｜　最后更新：2026-08-04

> **所有开发依据 Analytics，不是依据开发者感觉。**
> 现状：**尚未实施（GAP-02）**。这意味着当前所有产品判断都缺乏证据支撑。

---

## 1. 北极星指标

```
次日回访率（用户明天会不会再打开）
```

**理由**：Phoenix 的价值主张是"每天知道今天该怎么操作"。
如果用户明天不来，说明我们没有成为他的日常决策依赖 —— 其他指标再好看也是虚的。

## 2. 必须统计的指标

### 2.1 规模

| 指标 | 定义 |
|---|---|
| DAU | 日活跃设备数（按 `device_id` 去重） |
| MAU | 月活跃设备数 |
| 新增设备 | 首次出现的 `device_id` |

### 2.2 参与度

| 指标 | 定义 |
|---|---|
| 用户停留时间 | 单次会话时长中位数（非平均，避免长尾污染） |
| 首页点击率 | 首页有效点击会话 / 首页曝光会话 |
| AI 教练使用率 | 访问 `/coach` 的设备 / DAU |
| Discover 使用率 | 访问 `/discover` 的设备 / DAU |
| 持仓使用率 | 访问 `/portfolio` 的设备 / DAU |
| 「为什么」展开率 | 展开解释次数 / AI 结论曝光次数 ← **信任度代理指标** |

### 2.3 留存

| 指标 | 定义 |
|---|---|
| 回访率 | 次日再次打开的设备占比 |
| 7 日留存 | 第 7 天仍活跃 |
| 30 日留存 | 第 30 天仍活跃 |

### 2.4 反馈

| 指标 | 定义 |
|---|---|
| 反馈数量 | 按类型分组 |
| 反馈率 | 提交反馈设备 / DAU |
| 平均评分 | 星级均值 |

## 4. 实施规范

| 项 | 要求 |
|---|---|
| 身份 | 匿名 `device_id`（首次访问生成 UUID 存 localStorage），**不采集任何 PII** |
| 上报 | 批量缓冲，5s 或满 20 条 flush；`visibilitychange` 时强制 flush |
| 失败 | 静默丢弃，**绝不阻塞 UI**，不弹错 |
| 采样 | Beta 阶段 100% 采样（量小） |
| 埋点位置 | 统一封装 `src/analytics/track.ts`，**禁止**页面里散落 fetch |

## 5. 决策规则（数据怎么用）

| 条件 | 动作 |
|---|---|
| 某功能使用率 < 5% 且连续 2 个版本无改善 | **下线该功能** |
| 「为什么」展开率 < 10% | 说明可解释性没被感知 → 改前置展示，而不是加功能 |
| 次日回访率 < 20% | 停止一切新功能，专项攻留存 |
| 反馈中同一问题 ≥3 次 | 自动升级为 P1 |

> 数据的作用是**帮我们砍功能**，不是帮我们证明自己对。

---

## 6. 隐私声明

- 只采集**匿名行为数据**，不采集姓名/手机号/持仓明细/精确位置
- 首次启动需在引导页告知并提供关闭入口
- 用户可在「我的」页一键清除本地全部数据
